Why does the network layer exist?	<div style="text-align:left">Internetworking.<br><br>The link layer assumes one shared medium under one administrator. The internet is a huge collection of different mediums (Ethernet, Wi-Fi, 5G) run by different, often mutually distrustful administrators. The network layer is the piece that lets fundamentally different networks talk to each other at all.</div>	MSCS Network-Layer Module-2
What is IP's service model, and why is it built that way?	<div style="text-align:left">Best effort.<br><br>Packets can be dropped, reordered, or delayed, with no guarantee on any of it. IP has to interconnect networks of wildly different capability, so it can only promise the lowest common denominator every one of them can deliver. Guaranteeing more than the weakest link supports isn't possible.</div>	MSCS Network-Layer Module-2
Why do IP addresses have structure, unlike flat MAC (Media Access Control) addresses?	<div style="text-align:left">Scalability.<br><br>A flat address space needs one table entry per device, which is exactly what breaks once you have billions of devices. Structuring addresses into subnets lets a single table entry cover a whole range of addresses at once, with routers closer to the destination refining that further.</div>	MSCS Network-Layer Module-2
What does the /24 in 10.1.1.0/24 mean?	<div style="text-align:left">CIDR (Classless Inter-Domain Routing).<br><br>The number is the prefix length: the top 24 bits must match exactly, the rest are free to vary. A shorter prefix covers a bigger range of addresses; a longer prefix is more specific. This is what lets addresses be grouped and later aggregated into bigger blocks.</div>	MSCS Network-Layer Module-2
Two entries match the same destination, one broad prefix and one narrow one nested inside it. Which does a router use?	<div style="text-align:left">Longest prefix match.<br><br>The router always picks the most specific match available. This is why IP lookups use a trie (a prefix search tree) rather than the exact-match table an Ethernet switch uses. Overlapping prefixes are normal, since they're exactly how a bigger block gets subdivided.</div>	MSCS Network-Layer Module-2
What's the difference between forwarding and routing?	<div style="text-align:left">Data plane vs. control plane.<br><br>Forwarding is per-packet: look up the destination in a table, send it out the matching port. Routing is the coordination between routers that builds that table in the first place, by exchanging information with neighbors.<br><br>Same split shows up everywhere: a fast path acting on decisions a slower control process already made.</div>	MSCS Network-Layer Module-2
How does IP prevent forwarding loops, given it has nothing like Ethernet's spanning tree?	<div style="text-align:left">TTL (Time To Live).<br><br>Every hop decrements the field by one; if it hits zero, the packet is dropped. Blunt compared to computing a loop-free topology up front, but it needs no coordination and bounds the damage a loop can do.</div>	MSCS Network-Layer Module-2
What actually happens to a packet inside a router?	<div style="text-align:left">The line card pipeline.<br><br>Arrives at the ingress line card → look up the destination in the forwarding table → decrement the TTL and update the header → queue it in a buffer → cross the switch fabric to the output line card → transmit.<br><br>The hard part is the lookup: it's longest-prefix match against a trie, not the simple exact-match a MAC address table uses.</div>	MSCS Network-Layer Module-2
Routers evolved from a shared bus to a switching fabric like a crossbar. Why?	<div style="text-align:left">Parallelism.<br><br>A shared bus can move only one packet at a time between line cards, the exact same bottleneck as a shared Ethernet cable. A crossbar fabric gives separate input/output pairs their own physical path, so multiple transfers happen at once.<br><br>A shared resource serializes everything passing through it; dedicated paths parallelize it, at the cost of needing specialized hardware.</div>	MSCS Network-Layer Module-2
How does a link-state protocol like OSPF (Open Shortest Path First) compute routes?	<div style="text-align:left">Full map, local computation.<br><br>Every router floods what it knows about its own directly connected links to the whole network, until every router has converged on an identical picture of the topology. Each router then runs Dijkstra's algorithm independently on that shared map to build its own forwarding table.</div>	MSCS Network-Layer Module-2
How does BGP (Border Gateway Protocol) differ from a link-state protocol like OSPF?	<div style="text-align:left">Partial view, path exchange.<br><br>A BGP router never sees the full topology. It only learns the paths its neighbors choose to advertise, each one a full list of ASes (Autonomous Systems) the traffic would cross. That list doubles as the loop check: if a router's own AS is already in an advertised path, it rejects that route.</div>	MSCS Network-Layer Module-2
Does BGP just pick the shortest available path?	<div style="text-align:left">No. Business first.<br><br>ASes have real financial relationships (customer, provider, peer), and an AS can refuse to carry someone's traffic for free even if that path is shorter. Local preference and business policy are checked before path length. Internet-scale routing is shaped by contracts as much as by topology.</div>	MSCS Network-Layer Module-2
You know a server's IP address. How does your machine find its MAC address?	<div style="text-align:left">ARP (Address Resolution Protocol).<br><br>Broadcast a request asking "who has this IP," the owner replies with its MAC address, and the answer gets cached locally for next time. This is the glue connecting the IP addressing you actually use to the MAC addressing the link layer runs on underneath.</div>	MSCS Network-Layer Module-2
How does a laptop get an IP address when it joins a network?	<div style="text-align:left">DHCP (Dynamic Host Configuration Protocol), in almost every case.<br><br>Discover, offer, request, acknowledge, all automatic on connecting. Static assignment, manually configuring one fixed address, is the alternative, mostly reserved for servers that need a stable, known address.</div>	MSCS Network-Layer Module-2
Ping, traceroute, and iperf each answer a different diagnostic question. Which?	<div style="text-align:left">Reachability, path, and throughput.<br><br>• <b>Ping</b> (via ICMP) checks a host is up and times the round trip<br>• <b>Traceroute</b> reuses the TTL trick, sending packets with increasing TTL to map every hop along the route<br>• <b>Iperf</b> measures actual maximum throughput, isolating whether a slowdown is the network or the application<br><br>Reach for the one that matches the symptom, not always ping first.</div>	MSCS Network-Layer Module-2
