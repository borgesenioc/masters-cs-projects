Why does the transport layer exist?	<div style="text-align:left">Multiplexing.<br><br>IP gets a packet to a host, but a host runs many applications at once.<br><br>IP alone doesn't say which application the data is for → transport layer adds that missing piece.</div>	MSCS Transport-Layer Module-3
What are the two addresses in the transport header, and what do they identify?	<div style="text-align:left">Source port + destination port.<br><br>Identifies a specific process on the host → not a machine, not a network card.</div>	MSCS Transport-Layer Module-3
UDP vs TCP — what's the core tradeoff?	<div style="text-align:left">UDP = connectionless, no setup, no guarantees, just ports on top of best-effort IP.<br><br>TCP = connection-oriented, adds state, ordering, reliability, and congestion control.<br><br>∴ pay in complexity to get the guarantees.</div>	MSCS Transport-Layer Module-3
What three things can go wrong with delivery that reliable transfer has to fix?	<div style="text-align:left">Loss → link errors or buffer overflow drop packets.<br><br>Reordering → dynamic routing can change the path mid-stream.<br><br>∴ TCP can't assume the network delivers what you sent, in the order you sent it.</div>	MSCS Transport-Layer Module-3
How does TCP know which bytes arrived, and which didn't?	<div style="text-align:left">Sequence number = position of the first byte in this segment.<br><br>Acknowledgment number = next byte the receiver expects.<br><br>Gap between the two = what's still missing.</div>	MSCS Transport-Layer Module-3
TCP decides to retransmit. What triggers that decision?	<div style="text-align:left">Timeout → waited about one round-trip-time, nothing came back.<br><br>Duplicate ACK → same ack number arrives more than once, implying later data already arrived around a gap.<br><br>Duplicate ACK is the stronger of the two signals.</div>	MSCS Transport-Layer Module-3
What is flow control, and how does TCP implement it?	<div style="text-align:left">Protects the receiver, not the network.<br><br>Receiver advertises free buffer space via the receive window.<br><br>Sender caps in-flight, unacknowledged bytes to that number.</div>	MSCS Transport-Layer Module-3
Why does TCP need a handshake before sending real data?	<div style="text-align:left">Both sides hold state: sequence numbers, buffers, windows.<br><br>That state needs agreement before either side commits resources.<br><br>Three-way handshake = mutual sequence number exchange, each direction confirmed independently.</div>	MSCS Transport-Layer Module-3
What is congestion, mechanically, inside a router?	<div style="text-align:left">Send rate falls below receive rate on some output link.<br><br>The buffer absorbs the mismatch temporarily, then fills, then drops.<br><br>Retransmitting into an already-congested link makes it worse, not better.</div>	MSCS Transport-Layer Module-3
What's the difference between congestion control and flow control?	<div style="text-align:left">Flow control protects the receiver from being overwhelmed.<br><br>Congestion control protects the network from being overwhelmed.<br><br>Same window mechanism, two different things being protected.</div>	MSCS Transport-Layer Module-3
How does TCP detect congestion, given it can't see inside the network?	<div style="text-align:left">Implicit signals only: packet loss, and rising round-trip time.<br><br>No direct visibility into router queues → inference from symptoms at the edge.</div>	MSCS Transport-Layer Module-3
How does TCP's AIMD (Additive Increase, Multiplicative Decrease) actually behave, and why that shape specifically?	<div style="text-align:left">Increase linearly, one step per round-trip-time → cautious probing.<br><br>Decrease multiplicatively, cut by half on loss → fast retreat.<br><br>The asymmetry is deliberate: it's what keeps competing flows converging toward a fair, stable equilibrium instead of oscillating or starving each other.</div>	MSCS Transport-Layer Module-3
