Why does the application layer exist?	<div style="text-align:left">Meaning.<br><br>Transport gets bytes reliably between two processes.<br><br>It says nothing about what those bytes mean, or how to find the right process in the first place.</div>	MSCS Application-Layer Module-4
Why can't applications just use IP addresses directly, the way the network layer does?	<div style="text-align:left">Human-unreadable, and one IP = one machine.<br><br>A service like YouTube runs on many machines across many locations.<br><br>DNS (Domain Name System) decouples the name you use from wherever the service actually lives.</div>	MSCS Application-Layer Module-4
What does a DNS resource record actually store?	<div style="text-align:left">Name → value, tagged by type.<br><br>Type A: name → IP address.<br><br>Type NS: domain → authoritative name server.<br><br>Same lookup mechanism, different meaning per type.</div>	MSCS Application-Layer Module-4
DNS resolution walks down a hierarchy of servers. What's the shape of that walk?	<div style="text-align:left">Root → top-level domain → authoritative server.<br><br>Each level knows only enough to point you one level deeper, not the final answer itself.</div>	MSCS Application-Layer Module-4
Recursive vs iterative DNS query — what's the actual difference?	<div style="text-align:left">Recursive: your resolver does the walking → you get a final answer.<br><br>Iterative: each server hands back a referral → you follow it yourself.<br><br>Same hierarchy, different party doing the legwork.</div>	MSCS Application-Layer Module-4
DNS root servers are a single, well-known set of addresses, yet handle massive global load without one location becoming a bottleneck. How?	<div style="text-align:left">Anycast.<br><br>Same IP address, announced from many physical locations.<br><br>BGP routes each requester to whichever announcement is topologically closest → redundancy and load distribution from ordinary routing, no special protocol required.</div>	MSCS Application-Layer Module-4
What problem do sockets solve for the programmer?	<div style="text-align:left">Abstraction over the OS network stack.<br><br>Link, network, and transport are protocols implemented inside the operating system.<br><br>A socket is the handle an application gets to use them, without touching that implementation directly.</div>	MSCS Application-Layer Module-4
In socket programming, what's the actual difference between a client and a server?	<div style="text-align:left">Role, not capability.<br><br>Server: bind → listen → accept, then waits.<br><br>Client: connect, initiates.<br><br>Same socket API underneath both.</div>	MSCS Application-Layer Module-4
An application protocol has to define three things beyond "send some bytes." What are they?	<div style="text-align:left">Syntax → field format.<br><br>Message types → request/response? streaming?<br><br>Semantics → what the fields mean.<br><br>Skip any one of these and the two ends can't actually understand each other, even with a perfect transport underneath.</div>	MSCS Application-Layer Module-4
Two machines disagree on byte order (endianness) or struct padding. What are the two strategies for handling that mismatch?	<div style="text-align:left">Canonical form: both sides always convert to/from one shared format.<br><br>Receiver-makes-right: sender ships its own native format plus a description of it, receiver converts.<br><br>Tradeoff: uniform simplicity vs. fewer conversions but more complexity.</div>	MSCS Application-Layer Module-4
HTTP is stateless and request/response. What did each major version actually add, and why?	<div style="text-align:left">1.0 → one object, one new TCP connection, every time.<br><br>1.1 → persistent connections, since paying the handshake and slow-start cost per object was wasteful.<br><br>2.0 → multiplexing, since even persistent connections still serialized requests one at a time.<br><br>3.0 → swaps TCP for QUIC, since TCP loss recovery blocks every stream on the connection at once, and QUIC recovers per-stream.</div>	MSCS Application-Layer Module-4
How does gRPC (Google Remote Procedure Call) differ from a REST/JSON API doing the same job?	<div style="text-align:left">RPC (Remote Procedure Call) illusion: call a function locally, stub code serializes it, sends it over the network, the far side calls the real function.<br><br>Protobuf (binary, schema-defined) instead of JSON (text, self-describing) → smaller payloads.<br><br>Tradeoff: both sides must have the shared schema ahead of time.</div>	MSCS Application-Layer Module-4
